## 1. HOME SCREEN LAYOUT

**Header (keep the title style, remove the gear icon)**
- Title "QuickScan PDF" and the storage line "X used on device", as they are now.
- Remove the settings gear icon from the header. Settings is already a tab.

**Segmented toggle (replaces the current folder strip and sort chips)**
- Two options, full width of the content area, equal widths: **All files** and **Folders**.
- The selected option has a filled accent background (`#2563EB`, white text). The unselected option has a light surface with a border and muted text.
- Default to **All files** on launch. Switching views doesn't trigger an ad.

**View 1: All files**
- A single scrollable list, grouped by date sections.
- Section headers follow the sketch:
  - **Recent**: documents created or opened in the last 24 hours that aren't in a earlier group. (Put "Recent" first if any exist.)
  - **Yesterday**: documents created yesterday.
  - **Date headers** for older documents, formatted like `20 OCT, 2026` (uppercase month, day, year). Use the device locale if it's easy, otherwise this format.
- Within each section, documents are sorted newest first.
- Each document row: thumbnail on the left, title, page count and size on the second line, and the three-dot menu on the right. Long titles truncate with an ellipsis.
- If a document is in a folder, show the folder name as a small muted label under the title. Unfiled documents show nothing extra.
- Tapping a row opens the viewer. The three-dot menu keeps its existing actions, including **Move to folder**.
- **Sorting:** the date sections are the default sorting. Add one small sort icon button in the list header (aligned right, above the first section) that opens a menu with **Oldest first**, **Name A–Z**, **Size (largest first)**, and **Recently opened**. Choosing one switches the list to a flat list sorted by that option (no date headers). Choosing **Newest first** or the default returns to the date sections. Keep the choice saved between launches.
- Empty state (no documents at all): centered icon, heading "No scans yet", and "Tap the camera button below to scan your first document."

**View 2: Folders**
- A 2-column grid of folder tiles, matching the sketch.
- Each folder tile: a folder icon at the top, the folder name in bold, and a muted scan count below it (for example "3 scans"). A thin border and the standard 12px corner radius. No heavy shadow.
- After the last folder, a dashed-border tile with a plus icon and the label "New folder".
- **Empty state (no folders yet):** instead of the grid, show one large centered block with a dashed border and the heading **"Create your first folder"**, a short line underneath ("Group your scans by subject, like Work, School, or Receipts"), and a plus button. Tapping it starts the create flow.

**Create folder flow**
1. Tap **New folder** (or the empty-state block).
2. A name dialog opens. Keep the existing rules: trim spaces, 40 characters max, no empty names, no duplicates (case-insensitive).
3. After the name is saved, open the **Add scans** screen:
   - Header: "Add scans to [folder name]", a back arrow, and a **Done** button.
   - A list of all scans that are not already in this folder, sorted newest first, each with a round checkbox on the right.
   - Tapping a row toggles its checkbox. A bottom button reads "Add 3 scans" (the count updates live) and is disabled when nothing is selected.
   - A secondary text button **"Skip for now"** creates the folder empty and returns to the folder grid.
   - Confirming moves the selected scans into the folder by setting `folderId`. The PDF files don't move.
4. After confirming, go to the folder detail screen.

**Folder detail screen**
- Header: back arrow, folder name, and a three-dot menu with **Rename** and **Delete folder** (existing behavior and the existing confirmation text, which says documents move to All files and nothing is deleted).
- Below the header, the same document rows as All files, sorted newest first.
- A floating **Add scans** button at the bottom of the list (above the bottom nav) that opens the same Add scans screen for this folder.
- Empty state: "This folder is empty" with the **Add scans** button.

**Move to folder (existing, keep working)**
- The three-dot menu on any document row still opens the Move to folder sheet, with every folder and **Unfiled**, plus **New folder**. This must keep working exactly as it does now.

## 2. BOTTOM NAVIGATION BAR (fixed, never moves)

- The bar is pinned to the bottom edge of the screen, above the Android gesture area (use the safe-area bottom inset). It is not part of the scrolling content and it is not pushed by anything else on screen.
- Three tabs: **Home**, **Tools**, **Settings**. Keep the existing icons, labels, and the accent color for the active tab.
- The bar has a fixed height. The content above it has a bottom padding equal to the bar's height plus the safe-area inset, so the last list item is never hidden.
- Hide the bar on the Camera, Editor, Share, and PDF viewer screens, as it does now.

## 3. CAMERA BUTTON (docked in the bar)

- The camera button is a **round accent button docked in the center of the bottom bar**, rising slightly above the bar's top edge (about 16–20dp), like a center tab button. It is not a floating button over the ad.
- There must be no large empty gap between the camera button and the bar.
- Tapping it starts a new scan, exactly as the current FAB does.
- It uses the accent blue `#2563EB` and a white camera icon. Keep its size consistent in both themes.
- The Home, Tools, and Settings tabs are evenly spaced around it. The Tools and Settings tabs keep the same vertical alignment as Home.

## 4. AD SLOT (fixed, never pushes the nav bar)

- The banner sits in a **fixed slot directly above the bottom bar**, full width, with a reserved height equal to the standard adaptive banner height (or 50dp if the adaptive size can't be known up front). The slot's height is reserved even before an ad loads, so the layout never jumps when the ad appears.
- If the ad fails to load, keep the slot's reserved space but render nothing inside it, or collapse the slot cleanly. Pick one and make sure the list above doesn't jump when the state changes. (Recommended: keep the reserved space so nothing moves.)
- The slot must not overlap the camera button, the document list, or the folder grid. Leave a 24dp gap between the slot and the top edge of the raised camera button, or move the slot so the button never covers it.
- The banner stays on the Home tab only. It doesn't appear on Tools, Settings, Camera, Editor, Share, or the viewer (the viewer banner from Release 2 stays as it is).

## 5. ADS THAT DON'T LOAD IN THE DEVELOPMENT BUILD

The owner tested a development build and saw:
- The **rewarded ad** on OCR showed "reward ad failed to load."
- The **app-open ad** never loaded.
- The **banner** loads correctly.

Do these in order:
1. In `__DEV__`, log every ad's load and failure events with the full error code and message from the SDK (for the rewarded, app-open, and interstitial ads). Don't hide the error behind a generic message.

6. If the logs show a real configuration error (for example, a missing native module, a wrong ID format, or an unsupported format), fix that root cause.
